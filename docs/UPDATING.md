# 最新GⅠデータを更新する

公開版は、運営者が確認した `dist/data/current.json` を起動時と更新ボタンで読み込む。JRAへのスクレイピングや自動同期はしない。確認日時を変えるだけで情報を新しく見せないこと。

## 今回の確認版

- 出典確認：2026-10-29 11:35 JST。
- 次回の対象：2026-11-01 天皇賞（秋）、東京・芝2000m。
- 2026-10-26公表のプレレーティングに掲載された登録17頭。
- 出馬表ページは10月29日公開予定の表示だった。最終出走、馬番、枠、騎手、当日の馬場は未確認。
- 番号は五十音順の仮ID。全頭 `frame: null`、`jockey: "未確認"`、`style: "neutral"`。斤量は年齢・性別による定量規定を使用。
- エリザベス女王杯、マイルCS、ジャパンCは日程のみ。出走馬は作成していない。

## 確定出馬表が出たら

1. JRAの出馬表を開き、登録17頭から実際の出走馬への変更を確認する。
2. `dist/data/current.json` を別名でコピーして編集する。`races[0]` の馬名と照合し、`number` を実馬番、`frame` を実枠、`jockey` を確認した騎手名、`weight` を確定斤量へ変更する。
3. `entryStatus` を `declared`、`numberStatus` を `official` に変更する。枠順未確定なら `temporary` と `frame:null` を維持する。未確認なのに確定扱いへ変えない。
4. 各 `sources` の説明を更新し、確認した実時刻を `checkedAt` にタイムゾーン付きで記録する。カタログ全体と収録レースの時刻を揃える。事前評価公表日 `ratingAsOf` は元資料の日付を保つ。
5. 以下を実行して検証する。

```sh
node tools/update-catalog.mjs path/to/checked-catalog.json
npm test
npm run build
```

6. `dist/index.html` で、仮IDから実馬番になったこと、人数、騎手、出典、シミュレーションを確認する。
7. GitHubへ変更を送る。Pagesワークフローを手動実行して新しいビルドを公開する。利用者の更新ボタンは公開済みのデータだけを取得する。

脚質や適性の補正は公式の事実と分けて設定する。欠けたレーティングは推測値で埋めずnullを維持する。レース後の評価や着順を事前入力へ追加しない。

## 次のGⅠに切り替える

`schedule` に出典付きの開催日を登録する。資料が確認できたレースだけ `races` に追加する。2歳戦など全頭の評価が欠損するレースは、このモデルでは実行できない。ダートも未対応。

各レースには一意のIDを割り当て、保存済み予想の元データを書き換えない。同じシードでも仮IDを実馬番へ変更すると乱数割当が変わる。確認前後の比較では、ノートに保存した旧入力を復元する。

開催日が過ぎたデータは画面に「開催日を経過」と表示する。次のGⅠが日程だけの場合、過去データを最新として選択しない。24時間以上経過した確認版と開催当日は再確認を促す。

## 失敗時の動作

- 取得失敗、壊れたJSON、200KB超、未来の確認日時、古い配信、日程不一致は反映しない。
- 新しい版は候補として表示する。反映ボタンを押すまでは作業中の予想を保持する。
- 反映時は条件が初期化されるため、必要な予想を先にノートに保存する。
- ZIPを直接開く場合は同梱版で動く。最新のZIPへ入れ替えるか、確認した単一レースJSONを読み込む。
