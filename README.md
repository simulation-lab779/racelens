# RaceLens GⅠ Simulator

**次のGⅠを、走らせよう。**

実在するGⅠの登録馬・事前レーティングを使い、予想とレースシミュレーションを楽しむWebアプリです。JavaScript / Canvasで実装し、GitHub Pagesに公開できる構成にしています。

v0.3.0では **2026年11月1日・天皇賞（秋）** の登録17頭を収録しました。出典確認は **2026年10月29日11:35（日本時間）**。その時点のJRA出馬表ページは公開予定の表示だったため、確定出走・馬番・枠順・騎手は未確認です。番号は画面内の「仮ID」であり、実際の馬番ではありません。

初期実装はAI支援で作成しています。機械学習の学習済みモデルや、予測精度・収益性を実証したサービスではありません。

## すぐに試す

配布ZIPを解凍し、**`racelens-replay/dist/index.html`** をChromeまたはEdgeで開きます。以前の版を持っている場合は、更新したZIPをもう一度ダウンロードしてください。

1. 天皇賞（秋）を選び、応援する馬を指定する。
2. 「発走」で観戦する。停止、速度変更、シークが可能。ゴール前はゆっくり再生する。
3. ゴール後に仮想1〜3着を確認する。「別の展開で走る」で異なる試行を観戦する。
4. 脚質の仮説、馬場、ペース、適性を変え、予想を再計算する。
5. ノートへ入力・設定・予想・シードを保存する。
6. 過去レースでは実結果を開き、答え合わせができる。

最新GⅠの脚質は初期状態で全頭「未設定」です。根拠のない有利不利を作らないため、この状態ではペースだけを変えても相対評価は変わりません。各馬の位置取りを仮定すると、展開補正が働きます。道中の位置変化は観戦用の仮想演出です。

動きを減らすOS設定が有効な場合は、アニメーションを省略して仮想着順を表示します。

## 機能

- 次のGⅠの日程、登録・確定の状態、出典確認日時を表示。
- 確認から24時間経過、開催当日、開催日経過を日本時間で判定。
- 公開サイトでは運営者が更新したデータを起動時と更新ボタンで確認。新しい版の反映前に予想を保存できる。
- 1,000 / 2,000 / 10,000回のモンテカルロ試行を集計。
- 同じ入力・シード・モデル版で計算と観戦を再現。
- ブラウザ内に予想ノートを最大100件保存、復元、JSON書出し。
- 実レースJSONの読込・書出し、予想CSV出力。
- 過去2レースの実着順、同着、単勝・馬連の仮想精算。

**更新ボタンはJRAを自動収集する機能ではありません。** 運営者が出典確認後に公開した `data/current.json` を取得します。ZIPを直接開く場合は同梱データで動きます。ライブオッズ、取消・乗り替わりの自動追従、自動購入はありません。

## 開発する

Node.js 22以上。外部パッケージのインストールは不要です。

```sh
npm test
npm run build
npm start
```

`http://127.0.0.1:4174` を開きます。`src/` を編集後は再ビルドしてください。HTML・CSS・JavaScriptを `dist/index.html` にまとめ、更新用の `dist/data/current.json` も出力します。GitHub Pagesのリポジトリ配下のURLでも相対パスで動作します。

## 予想のしくみ

基礎値は当年と前年の事前評価があれば `当年×0.65 + 前年×0.35`、片方のみならその値。両方なければ出走馬の中央値を仮置きし、欠損表示と大きなばらつきを付けます。

```text
評価 = 基礎値 + (58 − 斤量) × 2
     + コース補正 × 1.3 + 騎手補正 × 0.7
     − 脚質位置係数 × ペース × 3
     + 道悪補正 × 馬場レベル × 1.5
```

未設定脚質の係数は0。適性と騎手補正の初期値も0です。各試行に乱数変動を加え、着順を集計します。表示の「1着率」は **モデル内で1着になった割合** であり、実際の勝率ではありません。

係数は未較正の仮説です。距離区分、輸送、調教、馬齢成熟、当日の体調、馬同士の干渉などは未実装。コースも実走路の形状や距離配分を再現しない模式図です。詳細は [docs/MODEL.md](docs/MODEL.md)。

## 次回データとGitHub公開

確定出馬表が出たら [docs/UPDATING.md](docs/UPDATING.md) の手順で馬番・枠・騎手を更新します。次のGⅠの資料を追加すると、日付から初期表示を選びます。

GitHubへのアップロードと公開はまだ実施していません。手元の操作確認後、[docs/GITHUB.md](docs/GITHUB.md) に沿って公開できます。

1. 空のリポジトリを作り、`package.json`、`src`、`tests`、`.github` などが直下に来るようアップロードする。
2. `Settings → Pages → Source` を **GitHub Actions** にする。
3. `Actions → Publish GitHub Pages → Run workflow` を実行する。

ドットで始まる設定ファイルも含めます。認証情報や個人の予想ノートはアップロードしません。

## 検証状況と記録

44件の自動テストが成功。アプリ起動から観戦ゴール・ノート保存・過去結果比較までをDOMの代替オブジェクトでも検証しています。これは実ブラウザでの操作確認とは異なります。実ブラウザ・スマートフォン・GitHub上のCIと公開は未確認です。[docs/VALIDATION.md](docs/VALIDATION.md) に詳細を記載しています。

ブラウザの保存領域は端末間同期されず、消去するとノートが失われます。ノートJSONの再取込は未実装です。ユーザー読込のレースは常に未検証として扱います。実結果の非表示は遊び方の工夫であり、改ざん防止機能ではありません。

就活で説明するときは、実際に理解・改修・検証した内容を [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) に記録してください。AI支援と自分の担当を区別します。
